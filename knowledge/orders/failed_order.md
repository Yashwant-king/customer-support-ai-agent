# Failed Order Policy

## Failed Orders

An order may fail because of problems during order processing, payment, or other system-related issues.

The support agent should verify the order information before explaining the problem to the customer.

## Customer Information

The customer should provide:

- Order ID
- Description of the problem

The support system should use available database information to determine the current order status and payment information.

## Payment Verification

If an order appears to have failed, the support agent should check whether a payment was recorded for the order.

A failed order must not automatically be treated as a successful payment.

## Refund

If payment was captured for an order that ultimately failed, the case should be handled according to the refund processing policy.

The support agent must not promise an exact refund date unless supported by the available information.

## Important Rules

The support agent must never:

- Invent the reason an order failed.
- Claim that payment was successful without payment information.
- Promise a refund without verifying the relevant information.

## Escalation

Escalate the case when:

- Payment information conflicts with the order status.
- The customer disputes the failed-order decision.
- The available information is insufficient.
- The customer requests an exception.
